## What I was doing

Fixing four defects reported from a real project (`lust-lab`) using Trellis. All four were
confirmed real, all four are fixed, verified and committed as `a101637`. Nothing is half-done.

**Fixed and verified:**

1. **Gates were not concurrency-safe.** The Stop hook and `deliver-run.sh` both run them, and gates
   bind ports and name containers. The collision presents as `ERR_CONNECTION_REFUSED`, which reads as
   a broken product rather than as contention. New `.claude/lib/gatelock.py` — a cooperative lock
   that reclaims a lock whose owner died or that exceeds `STALE_AFTER`, and releases even when the
   gates raise. Both `verify-gate.py` and `deliver-run.sh` acquire it. 5 tests.

2. **`Write()` deny rules did nothing.** Every protected path in
   `.claude/profiles/autonomy.settings.json` now carries both `Edit()` and `Write()`, with
   `$denyNotes` recording that Edit governs changing an existing file while Write governs creating
   one — so guarding only Edit left a run free to drop a *new* hook into `.claude/hooks/`. The
   deeper point is also written down: permission-rule semantics belong to the harness, and a rule
   that silently does nothing looks identical to one that works, so the real control is the
   fingerprint. Which is where this found what the report did not: `.github/workflows` was in the
   deny list but **not** in `guard_fingerprint()` in `run-spec.sh`. It is in both now.

3. **CI repair could not authenticate and burned the budget anyway.** Repair output is captured to
   `REPAIR_OUT` (a variable, not a redirect) and grepped for OAuth/session/401 patterns; on a match
   it exits 1 immediately saying "could not authenticate". Building the test exposed why the log was
   empty: output had been appended to `docs/runs/`, which exists on the default branch but not on
   the agent branch, so the redirect went nowhere.

4. **Delivery was not resumable.** Killed after opening a PR, a re-run died at `gh pr create` with
   the work already pushed. It now checks `gh pr view "$BRANCH" --json url`, reuses the open PR and
   updates its body.

Also fixed a guard false positive: `guard-tampering` spanned newlines, so an unrelated `rm` on one
line matched a `.claude/hooks` path on another — it blocked an ordinary lint command during this
session. Now confined to a single command segment, with four cases proving real tampering is still
caught and four proving neighbours are not.

**Full suite green:** guard 102, secrets 26, risk 32, mockup 8, integrity 11, loop 6, deliver 18,
frontmatter 20, gatelock 5. Lint clean. All references resolve.

**The recurring root cause across every field report so far** — now written into the `clean-code`
